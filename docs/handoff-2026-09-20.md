## What this project is

tinycmdr (renamed from `tinycmdr` on 2026-09-20) is a single-file agent harness: one Python file
plus a skills folder, driven by DM from Mattermost, by a local page, or by a session in a
terminal. It runs on six household machines and is about to become public.


**Packaging.** The download is runtime only: 49 files/550 KB became 19 files/365 KB by dropping
`tests/`, `CHANGELOG.md`, `MANIFEST.txt` and `launch-tinycmdr.sh`. The reference config is checked
against the code by VALUE (not presence), the installer's required-file list is checked against the
package at build time, and the public gate refuses fleet identity, secrets, and the operator's
surname.

**The installer is interactive.** Double-clicked, it asks which doors to set up (any combination of
a local page, a Mattermost bot, sessions by hand), then the model endpoint and model id, then the
page token (generated, or type your own), shows a summary, and waits for a yes. A chat account is
optional: with no token it sets up the local page instead and registers no chat task. An existing
install is a question, not a `-Force` error.

**The web page's token.** The installer hands over a link that already carries the token
(`http://127.0.0.1:8787/?token=...`); the page takes it from the link, remembers it, and re-asks if
the server says 401, naming `web-token.txt`. The link is URL-escaped (`[uri]::EscapeDataString`),
because "type your own password" invites `&`, `#`, `+`, `%` and spaces, each of which means something
else in a query string.

**The page was dead in every browser, in every shape of 1.0.0, until the night of 2026-09-20.** Three
`askToken()` string literals held a SINGLE backslash-n in the Python source, so Python did the escape
and the browser received real newlines inside JS string literals - the whole `<script>` was a
SyntaxError, so no line of it ran: Send did nothing, Enter inserted a newline, the token stayed in the
address bar and the version chip stayed empty. Fixed in `tinycmdr.py`. `tests/test_webui_page.py` graded
the page sliced out of the RAW SOURCE TEXT, which still reads as valid JavaScript, so it was green on a
page no browser could run; it now renders the page the way the server does, its DOM shim covers
`location`/`history`, and it grades the installer's link handover in both directions.
`tests/test_webui_browser.py` is the suite that catches this class (it was failing 13 checks on that
tree, and had not been run since the page changed).

**The page's live reporting, all three gaps closed (night, second pass).** A run now draws its own
line in the transcript where it starts and edits it into `✅ Done - N step(s) in Ts · model X` when
it ends (before this, the Done text lived in the header alone and a reload erased it); the model's
REASONING streams into one dim, tail-capped line (`Destination.shows_reasoning`, page only - chat
keeps it off deliberately); and the heartbeat says `thinking · N chars` / `writing · N chars`
instead of printing a chunk rate as "tok/s" while the answer's char counter sat at 0 through the
whole think. Every one of these is server-side: the page's own JS did not change.

**A page-only install also failed its own readiness check.** The supervisor waited for the lock plus a
Mattermost answer, which an install with no chat account can never produce: it logged
`up but not ready after 90s` in the first two minutes and then booked every later exit as a FAILED
START (`uptime=1488s ready=False (consecutive failures 1)` on the Windows test box), heading for growing backoff
and an "tinycmdr keeps failing" announcement on a healthy bot. It waits for the doors the child was
actually asked to serve now - chat installs keep the old test, a `--web` child is ready when the page
answers - and `tests/test_supervise_ready.py` grades all three lanes against real children.

**Verified today on the Windows test box** (each of these was run, not assumed): the installer's wizard in
every lane (page, chat, page+chat, sessions-only), a token-less local install serving the page
(`{"ok": true, "version": "1.0.0"}`), the page's auth (`401` without the token, `401` with a wrong
one, `200` with the right one), a redo keeping a state file it found, and the public archive
unpacking to a clean tree. All 22 suites pass, `test_cli` at 168 checks.

That list was all SERVER-level, and it is how a page no browser could run passed every gate: `/api/health`
answering `ok` and the 401/200 checks say nothing about the page's own JavaScript. The page is now graded
in a real engine twice over - `test_webui_browser.py` (Edge through Playwright, typing and pressing Enter
on the composer) and a headless Edge run against an install made from the built
`tinycmdr-1.0.0-win-public.zip` (version chip `1.0.0`, the message sent, `web run ... started from the
browser`, no JS exceptions).

## How to work on it

```
build every shape      python maintenance/build-package.py [--public] [--public --macos]
                       python maintenance/build-cli-package.py
the console build      maintenance/build-cli-source.py then build-cli-fix.py - it is GENERATED,
                       never hand-edited
suites                 python tests/test_*.py            (22 suites, all green)
fleet build report     powershell -File maintenance/fleet-version-report.ps1   (read-only)
hosts and doors        skill 'fleet-access'; wssh.py for Windows hosts; \\host\C$ over SMB
build/release rules    skill 'tinycmdr-build-release' (the packaging and installer lessons)
```

Traps that cost time today, so they do not cost it again:

- **A probe install must pass its own `-TaskName`** (e.g. `tinycmdrProbe`) and unregister it. A
  probe that registers `tinycmdr` overwrites the operator's task, and a cleanup that only deletes
  folders leaves a task pointing at nothing.
- **`-VerifyOnly` never reaches the installer's package-integrity check.** Only a real install into
  a temp `-InstallDir` proves a package.
- **The `.cmd` wrapper always passes `-NoPause`**, so never gate questions on that flag: a real
  console decides whether to ask (`-NonInteractive` and a redirected stdin mean "do not ask").
- **Dropping a shipped file means editing four places** in lockstep (`SHIP`, `APP_FILES`, the
  installers' copy lists, and the installers' required list) - the required list is the one that
  breaks the install loudly.
- **Renaming a shipped file means grepping the packager**, not just the tree.
